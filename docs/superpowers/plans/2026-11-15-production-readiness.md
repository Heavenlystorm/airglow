# Airglow production-readiness implementation

The original qualification plan used v1.15.0 (b3ebb59) as its baseline. It retained the Python, native ES modules, WebView2 and Velopack architecture and targeted an unsigned local beta build. See the [qualification report](../../qualification-1.16.0.md) for completed checks and the [release guide](../../RELEASING.md) for the stable release process.

## Tasks

- [ ] 1. Isolate tests before app imports: all app storage, running markers, registry changes, helper subprocesses and hardware calls. Prove the real user state cannot change; run the existing suites safely.
- [ ] 2. Lifecycle: explicit old-process restart handoff (60-second bounded wait, no forced owner kill), idempotent cleanup covering partial startup, actionable missing-WebView2 preflight before hardware acquisition. Keep helper windows hidden/non-activating and validate the imported host repair.
- [ ] 3. Recovery: verified staging and rollback of helper files/tasks plus startup/health proof; recoverable multi-file Store transactions after instance lock and before migration/controller startup. Missing temperatures use configured failsafe for managed fans, never the old startup low-speed assumption; firmware-owned outputs stay untouched.
- [ ] 4. Effects: fix reverse Chase phase, integrate audio phase with dt, align spectrum behavior; reconcile truly required active effects before four-instance cap. Transactional scene replacement with desired/active revisions, renderer readiness, current-operation-only commit/rollback and lighting-only Undo. Reject stale effect-bound parameter edits. Capture last displayed frame, retire outgoing instances, prepare incoming up to four, commit persistence only when ready, and fade for 350ms. Existing 15-second host grace; restore previous scene on failure, retain last frame with Retry if restore fails. Off/safety cancel work immediately. Preserve automation precedence and save inactive manual base selections while clearly overridden.
- [ ] 5. Separate scene audition and renderer-backed thumbnails: extend preview service, never consume live instance capacity or use the hardware trial route. One focused animated preview, bounded still cache, sample rig/audio labels and visible failures/retry. Hardware changes only on explicit Apply.
- [ ] 6. UI fidelity: viewport zoom height, keyboard radio navigation/focus, presentation accent contrast, all 12 themes and 5 styles (Instrument/Number/Gauge/Graph/Bar) match their descriptions. Distinct temperature/capacity/load/power/network instruments, truthful telemetry/gaps/sources. Cancellable motion 120-220ms, reduced-motion/hidden lifecycle. Ctrl+K search actions for effects/profiles/workspaces/settings with explicit apply/open/cooling semantics.
- [ ] 7. Shared qualification gate for local packaging and future release workflows: Python, JS, imports/catalog, browser and packaged/native checks before accepting artifacts. Retain stable formats/IDs; additive scene revision/status fields and transition duration (350ms default, 0 disables).
- [ ] 8. Qualification/delivery: regressions/fault injection; 100 rapid switches; all four live slots plus isolated audition; visual frame parity; all themes/styles at widths390/700/1280/1920/3840 and scale90/100/120; normal/reduced motion, p95 frame interval <=25ms on 60Hz target and no attributable >100ms interaction stall; 10 app restarts; two-hour mixed soak; fresh/upgrade/silent/repair/uninstall/reinstall/offline/missing-runtime disposable environment checks. Backup and upgrade actual installed app via non-MSIX context; validate available NZXT/ASUS/OpenRGB/LHM hardware and user-triggered reboot/sleep. Deliver installer/portable/hashes/source/recovery instructions/evidence. Missing environments explicitly unverified, never substitute fixture results for hardware results.

## Execution and acceptance

Write meaningful failing regressions before nontrivial fixes. Keep tests isolated until the dedicated hardware integration check. Review each change and the integrated diff. Resolve reproducible failures in tested core flows before acceptance. The local artifact was 1.16.0-beta.1. The stable release requires its own source and package gates.

Journal contract: recover after single-instance lock, before migration; only validated app-owned paths, hashes and complete previous/candidate data; durable commit marker; without marker rollback, with marker complete forward; idempotent recovery; corrupt records preserve originals and block affected mutations with diagnostics. Never derive recovery paths from imported data.
